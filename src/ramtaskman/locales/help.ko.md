# ramtaskman · 수치 이해하기

gputaskman의 시각적 구조를 Linux, Windows, macOS 메모리에 맞게 적용했습니다.

| 필드 | 의미 |
|---|---|
| PSS | 개인 RAM과 공유 페이지의 비례 배분량 |
| USS | Private_Clean + Private_Dirty: 개인 상주 페이지 |
| RSS | 공유 페이지를 포함한 상주 페이지; 합산하면 중복 계산될 수 있음 |
| Swap | smaps_rollup의 Swap, shmem 스왑 제외; 공유 페이지가 중복될 수 있음 |
| SwapPSS | smaps_rollup이 집계한 공유 스왑의 비례 배분량 |
| RAM used | MemTotal − MemAvailable; 프로세스 합계와 다름 |
| Cache | Cached + Buffers + SReclaimable − Shmem; 사용 가능 메모리와 겹침 |
| PSI some | 하나 이상의 작업이 메모리를 기다린 시간 비율, 10초 평균 |

**RAM 막대:** 전체 너비를 사용하며 Linux OS 카운터를 익명 메모리, 파일 캐시(Cached − Shmem), 공유/tmpfs, 버퍼, 회수 가능/불가능 slab, 기타(계산된 잔여량), 여유 메모리로 나눕니다. 회계상 범주이며 순서는 물리 주소를 뜻하지 않습니다. 사용 가능 메모리는 회수 가능한 캐시를 포함하는 별도 지표이므로 추가 구간이 아닙니다. 프로세스의 clean/dirty와 PSS 상세는 전역 카운터와 겹치므로 **d**에 있습니다. 필드가 없거나 샘플이 일관되지 않으면 막대는 사용 중/사용 가능 메모리와 분류할 수 없는 이유를 보여 줍니다. 한 글자보다 작은 범주도 범례에 표시됩니다.

**앱 USS 막대:** USS가 완전한 상위 10개 앱과 나머지 완전한 앱을 보여 줍니다. 눈금은 샘플의 완전한 앱 USS 합계이며 전체 RAM이 아닙니다. 번호와 색상은 범례에 대응합니다. 부분 그룹은 제외하며 측정 범위를 명시합니다. 그룹화는 표와 같습니다. 구간은 물리 주소가 아닙니다.

**Windows/macOS:** USS와 RSS는 psutil에서 가져옵니다. 프로세스별 PSS, Swap, SwapPSS는 제공되지 않아 n/a로 남습니다. Windows의 개인 commit/pagefile은 디스크 스왑이 아닙니다. macOS의 RAM used는 psutil의 total − available이며 활성 상태 보기의 메모리 압력이 아닙니다.

**앱 그룹화:** Linux의 명시적인 systemd cgroup이 앱 인스턴스를 식별하며, 실행 파일이 다른 보조 프로세스도 포함할 수 있습니다. 서로 다른 사용자와 인스턴스는 분리됩니다. 이 식별 정보가 없으면 Windows/macOS를 포함하여 사용자 + 실행 파일을 사용하고, 경로를 읽을 수 없으면 사용자 + 이름을 휴리스틱으로 사용합니다. 검사 패널에 방법이 표시됩니다.

**검색과 필터:** **/**는 이름, 실행 파일, 정확한 PID로 검색하고 **f**는 사용자와 메모리 상태(**스왑 사용**, **부분 데이터**)를 선택합니다. 필터를 조합할 수 있습니다. 앱의 프로세스 하나가 검색이나 메모리 상태에 맞으면 앱이 일치하지만, 합계에는 모든 구성원이 유지됩니다. 프로세스 보기로 들어가도 필터를 유지합니다. 필터는 상위 30개 제한보다 먼저 적용되며 그래프와 대시보드는 전체 시스템을 설명합니다. 검색창에서 **Enter**는 표로 돌아갑니다. 제어 항목의 **Esc** 또는 **Reset**은 필터를 지우며, 프로세스 표의 **Esc**는 필터를 유지한 채 앱으로 돌아갑니다. 부분 데이터는 지원되는 카운터만 고려합니다. 알 수 없는 스왑은 스왑 사용을 뜻하지 않습니다.

**d**는 그룹 또는 프로세스의 RAM 상세를 엽니다. 익명/파일/shmem PSS, 개인·공유 clean/dirty, 익명 페이지, LazyFree, THP를 보여 줍니다. Linux 전용 필드이며 다른 시스템에서는 n/a입니다. 각 행은 겹치는 관점이므로 모두 합산하면 안 됩니다. 상세는 열 때 샘플을 고정합니다. 새로 고치려면 닫고 다시 여세요. **Esc** 또는 **d**로 닫습니다.

프로세스에서 **r** 또는 **Enter**를 누르면 Linux 영역 지도를 엽니다. 앱에서 **r**을 누르면 먼저 PID를 보여 줍니다. 각 프로세스에는 독립적인 가상 주소 공간이 있습니다. **d**의 막대는 PSS와 RSS를 각각 나누며 스왑은 상주 RAM에서 제외합니다.

지도에서 **v**는 RSS/가상 주소 전환, **s**는 정렬, **/**는 파일 또는 0x… 주소 검색, **f**는 유형/상태 필터, **z** 또는 **Enter**는 선택 영역 주변 확대, **r**은 새로고침입니다. **Esc**는 필터 지우기/확대 종료/뒤로 이동을 수행합니다. 지도는 가상 주소 순서이며 물리 프레임이 아닙니다. 빈 주소 공간은 가상 눈금에서 제외하고 │로 표시합니다. 한 글자보다 작은 영역도 표에서 선택할 수 있습니다. 유형은 매핑의 출처이며 내용이 아닙니다. 파일 매핑에도 개인 CoW 페이지가 있을 수 있고, 식별된 힙/스택만 그렇게 표시합니다. 샘플은 요청 시 읽고 경과 시간, 소요 시간, 읽기 한도를 보여 줍니다. Windows는 실험적인 가상 범위만 제공하며 macOS 영역 지도는 없습니다.

영역에서 **b**는 A를 고정하고 **r**은 B를 수집하며 **c**는 비교를 엽니다. 비교에서 **v**는 지표, **s**는 정렬을 바꾸고 **f**는 상태를 필터링하며 **Ctrl+B**는 A를 제거합니다. **Ctrl+S**는 샘플 저장, **Ctrl+O**는 오프라인 파일 열기입니다. 파일에는 메타데이터와 개인 경로가 포함될 수 있습니다. 누락된 데이터와 재구성된 영역은 n/a로 남습니다. 같은 구간이라고 같은 할당이거나 메모리 누수라는 증거는 아닙니다.

**n/a는 0이 아닙니다.** 앱 합계에서 값 하나라도 없으면 n/a입니다. 측정은 PSS/USS 측정 범위를 나타냅니다. 대시보드의 보이는 합계는 사용 가능한 측정값의 부분 합계이며 전체 시스템 RAM이 아닙니다. 읽기는 원자적이지 않아 수집 중 프로세스가 바뀔 수 있습니다. 다른 사용자, 샌드박스, procfs 권한 때문에 읽지 못할 수 있습니다. 자동 권한 상승은 없습니다. HugeTLB는 여기 표시되는 일반 RSS/PSS/USS 카운터에서 제외합니다.

프로그램은 메타데이터만 읽으며 /proc/PID/mem, cmdline, environment 또는 앱 내용은 읽지 않습니다.

**g** 앱/프로세스 · **Enter** 선택한 앱의 프로세스 · **Esc** 앱으로 돌아가기  
**s** 정렬 · **c** 그래프 · **a** 전체/상위 30개 · **m** 간단/전체  
**/** 검색 · **f** 필터 · **d** 상세 · **r** 영역 · **p** 일시 정지 · **?** 도움말 · **q** 종료

그래프는 최근 60개 샘플을 0–100% 눈금으로 표시합니다. 빈칸은 데이터 누락입니다. 간격은 측정 후 대기 시간이므로 실제 주기에는 스캔 시간도 포함됩니다.
